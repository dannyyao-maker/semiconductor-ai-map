# /更新地圖

用新資料更新 `data/` 的內容。這個指令只處理「新資料」，不重寫整張地圖。

使用者指定的範圍：$ARGUMENTS
（沒有指定時，就照下面第 1 步自己找新資料。）

## 開始前

1. 讀 `CLAUDE.md`、`決策紀錄.md`、`來源清單.md`（特別是「查證規則」）。
2. 依專案規則，**先把這次要處理的資料清單和預計步驟列給使用者確認**，再動手。
3. 每次最多處理 5 份新資料，避免用完額度；超過的話列出來，請使用者選。

## 第 1 步：找出新資料

把 `data/sources.json` 裡每個來源的 `asOf`，和現在可取得的最新資料比對：

- **在美國上市的公司**：用 `node tools/sec-fetch.cjs 代號 --form=表單 --since=日期 --list` 列出某日期之後的申報。
  - 年報：`10-K`（美國公司）、`20-F`（外國公司）
  - 季報：`10-Q`（美國公司）；外國公司的季報新聞稿和法說簡報在 `6-K` 的附件裡
  - 股票代號對照：台積電 TSM、日月光 ASX、聯電 UMC、ASML、NVIDIA NVDA、AMD、美光 MU、高通 QCOM、博通 AVGO、英特爾 INTC、Amkor AMKR、應用材料 AMAT、美超微 SMCI、Vertiv VRT、Equinix EQIX、亞馬遜 AMZN、微軟 MSFT、Google GOOGL、Salesforce CRM
- **`sources/` 資料夾**：使用者手動存進來的 PDF 或筆記，比對 `sources/` 裡有沒有還沒處理過的檔案。
- **其他來源**（TSIA、IEK、TrendForce、Stanford AI Index、台灣公司）：用網路搜尋找 `asOf` 之後的新資料。

## 第 2 步：讀資料、對照卡片

- HTML 文件：先用 `node tools/sec-fetch.cjs` 下載（或直接下載附件網址到 `sources/sec/`），再用 `node tools/find-text.cjs 檔案 "關鍵字"` 找原句。
- PDF：先用 `node tools/pdf-text.cjs 檔案.pdf` 取出文字（產生同名 .txt），再用 `find-text` 搜尋。這台電腦沒有安裝 PDF 轉圖片的程式（poppler），所以 Read 工具不能直接讀 PDF。掃描型 PDF 取不出文字時，請使用者改提供網頁版，或複製需要的段落。
- 對每一條可能受影響的內容（`issues`、`topics`、`business`、公司小卡），判斷：
  - **仍然正確**：在來源清單加上新來源，`asOf` 改成這次的日期。
  - **需要更新**：用自己的話改寫（不照抄原文），附上新來源。
  - **新的重要議題**：可以新增一條，但每個欄位最多 3–4 條；要新增就要替換掉最不重要的一條。
  - **跟原本內容衝突**：以官方一手資料為準，並在報告裡特別標出來。

## 第 3 步：寫回資料

- 新來源加進 `data/sources.json`，格式：`{ id, publisher, title, url, asOf, type }`，`type` 是「官方」「研究機構」或「媒體」。
- 改過的條目，`status` 一律改成「待審核」，`asOf` 改成這次日期。
- 遵守查證規則：二手資料要有兩個獨立來源，或追到官方資料；找不到根據的句子不能寫進去。
- 只寫商業面內容，不寫製程、規格等技術細節；專有名詞附英文；用繁體中文。
- 寫完後執行檢查：每個 `sources` 裡的代號都要在 `sources.json` 找得到。

## 第 4 步：記錄與收尾

1. 在 `查證報告.md` 最後新增一節「YYYY-MM-DD 更新：來源名稱」，用表格列出改了哪些內容、原本寫什麼、改成什麼、為什麼。
2. 執行 `node tools/review-list.mjs`，重新產生審核清單。
3. 用 `node tools/serve.mjs` 開網站，確認改過的卡片顯示正常。
4. 停下來給使用者看結果，經同意後做 Git commit，訊息寫「更新地圖：來源名稱」。
5. 如果做了重要決定（例如換來源、刪掉某個議題），寫進 `決策紀錄.md`。
